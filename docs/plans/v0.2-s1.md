# v0.2 S1: `patterns:` engine

Goal: a project declares its own patterns, using any component, path or name, and every agent is held to them by the same
lint and hooks as v1. Spec: [spec-v0.2.md](../spec-v0.2.md) §3, §4.1, §4.4, §6a.

Done when:

- a fixture with a custom `<LoadingState>` is enforced;
- a 2-app fixture enforces different page frames per app;
- the v1 baseline cases can be expressed as patterns and catch the same code;
- all v1 tests still pass.

## Scope

- **Core schema** `patterns:`. Each pattern has these fields:
  - `concern` (defaults to the pattern id)
  - `use` / `root` (refs of the form `module#Export`)
  - `files` (globs)
  - `scope`
  - `except` (`{path, reason}`)
  - `forbid`
  - `severity`
  - `status` (`decided` | `proposed`)
  - `why`
  - `reason`, required when the pattern overrides a parent pattern
  - `lock`, stored now and used in S2

  `forbid` entries take one of these matchers: `import`, `element`, `className`, `call`, `text`.
- **Concern catalog (minimal).** Core ships default signals for these concerns:
  - `loading`
  - `text-input`
  - `page-title`
  - `breadcrumb`
  - `confirm`
  - `toast`

  When a pattern has no `forbid`, it uses the catalog signals minus the modules listed in `use`. S4 extends the catalog and adds scan grouping.
- **Layered contracts.** When an `extends` entry resolves to a directory that holds `contract.yaml`, that directory is a parent contract:
  - Its rules, scopes and patterns are inherited.
  - Each pattern keeps its own base directory, so its globs stay relative to the contract that declared them.
  - A child that redefines a parent pattern id must give a `reason`.
- **Module resolution.** `@/…` and other tsconfig `paths` aliases resolve, as do relative paths, so the lint can:
  - tell that `import X from "../app/loading-state"` is the canonical module;
  - exempt the canonical component's own file from its pattern's `forbid`.
- **Lint.** `fcs/pattern` reports error-severity patterns; `fcs/pattern-warn` reports warn-severity ones, because ESLint fixes severity per rule. The checks are:
  - forbidden imports (module or named), elements, className tokens or regex, calls (`toast` also matches `toast.success`), and JSX text;
  - `root`, the default export's return roots, checked in files matching `files`.

  Per concern, only the most specific applicable pattern is used. A pattern that names `files` or `scope` beats one that names neither; after that a child contract beats its parent, and then declaration order decides. Files are exempt when they are:
  - the shadcn primitives directory;
  - `components/fcs/`;
  - the pattern's own canonical files.
- **Agent context.** `AGENTS.md` / `CLAUDE.md` get one line per pattern, using the project's names, with proposed patterns flagged.
- **Out of scope for S1:**
  - locking canonical components (S2)
  - baseline (S3)
  - `scan` (S4)
  - first-use detection and `adopt` (S5)
  - tokens (S6)

  The v1 rules stay as they are. Moving the baseline preset onto patterns waits until patterns have proved themselves on a real project.

## Tests

- core:
  - schema;
  - default forbid from the catalog;
  - layering: parent patterns, an override with and without `reason`, globs relative to their base;
  - most-specific selection.
- eslint:
  - each `forbid` kind;
  - `root`;
  - alias and relative resolution;
  - canonical file and primitives exempt;
  - a scoped 2-app fixture;
  - proposed status shown in messages;
  - warn split.
- equivalence: textarea, loading spinner, h1, and the page root written as patterns catch the v1 invalid cases.
- cli: `fcs check` and the post hook report `fcs/pattern` violations; `fcs build` writes the pattern lines.
