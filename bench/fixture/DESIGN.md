## UI contract (frontend-consistency)

_Generated by `fcs build` from `.design/` — do not edit this block; change `.design/` and rebuild._

These rules are enforced by lint after every edit. When a rule names a component, use that component — do not re-implement it.

- Never edit files under `components/fcs/`; they are locked. Change behaviour through `.design/` params.
- Never disable `fcs/*` lint rules (no `eslint-disable`). If a rule seems wrong for this case, stop and ask.
- Run `fcs check` before declaring UI work done.

### Forms

#### `forms.textarea.resize` — Textareas are not user-resizable
**Use:** `@fcs/textarea-field` · **Params:** `resize=none`

**Why:** A resize handle lets one field push the surrounding layout out of the grid and produces a different form height every session. Height is a design decision made per content type (rows), not by the user. Projects that need user resizing set params.resize to "vertical" — never "both" or horizontal, which break column widths.

Do:
```tsx
import { TextareaField } from "@/components/fcs/textarea-field";

<TextareaField label="Note" name="note" rows={4} />
```

Don't:
```tsx
<textarea className="resize-y" />
<Textarea className="resize" />   // shadcn primitive used directly in a page
```

### Layout

#### `layout.page-header` — Page title and breadcrumb come from the template
**Use:** `@fcs/page` · **Params:** `breadcrumb=nested`

**Why:** A breadcrumb on one screen and none on its sibling, or an h1 styled three ways, is the most visible drift between screens. Titles render only through the template, and whether a breadcrumb is shown is a project decision (params.breadcrumb), not a per-screen one. With "nested", pages below a top-level section (route depth 2+, e.g. /customers/[id]) must pass breadcrumbs; the last crumb is the current page and has no href.

Do:
```tsx
// app/customers/[id]/page.tsx
<Page
  title={customer.name}
  breadcrumbs={[{ label: "Customers", href: "/customers" }, { label: customer.name }]}
  actions={<Button>Edit</Button>}
>
  …
</Page>
```

Don't:
```tsx
<h1 className="text-2xl font-bold">{customer.name}</h1>
<Link href="/customers">← Back to customers</Link>     // instead of a breadcrumb
<Breadcrumb><BreadcrumbList>…</BreadcrumbList></Breadcrumb>   // hand-built in a page
```

#### `layout.page-template` — Every page renders a page template at its root
**Use:** `@fcs/page` · **Params:** `contentWidth=xl`

**Why:** Gutters, max width, vertical rhythm and where the title and primary action sit are what make screens feel like one product. Agents re-decide them per screen (max-w-5xl here, container py-10 there). The template fixes them once; a page only supplies content. Client-side views go inside the template, not around it.

Do:
```tsx
import { Page } from "@/components/fcs/page";
import { ListPage } from "@/components/fcs/list-page";

// app/customers/page.tsx
export default function CustomersPage() {
  return (
    <ListPage title="Customers" actions={<Button>New customer</Button>} toolbar={<CustomerFilters />}>
      <CustomerTable />
    </ListPage>
  );
}

// app/settings/page.tsx
export default function SettingsPage() {
  return <Page title="Settings"><SettingsForm /></Page>;
}
```

Don't:
```tsx
export default function CustomersPage() {
  return <main className="mx-auto max-w-5xl px-6 py-8">…</main>;   // hand-built frame
}
export default function CustomersPage() {
  return <CustomersView />;   // template hidden inside a client component
}
```

### Loading states

#### `loading.page` — Page and section loading uses the contract's loading pattern
**Use:** `@fcs/async-boundary` · **Params:** `pattern=skeleton`, `delayMs=300`

**Why:** Loading is the state users see most often, so a spinner on one screen and a skeleton on the next reads as two different products. The pattern is a project decision (params.pattern), not a per-screen choice. Skeletons keep layout stable while data arrives; the delay avoids flashing a loading state for fast responses. Spinners remain correct inside buttons for an in-flight action.

Do:
```tsx
import { AsyncBoundary, PageSkeleton } from "@/components/fcs/async-boundary";

// Server data: wrap the async part
<AsyncBoundary skeleton="list"><CustomerTable /></AsyncBoundary>

// app/customers/loading.tsx
export default function Loading() { return <PageSkeleton variant="list" />; }

// Client data (React Query / SWR)
if (isLoading) return <PageSkeleton variant="detail" />;
```

Don't:
```tsx
<Suspense fallback={<Spinner />}>…</Suspense>
if (isLoading) return <Loader2 className="animate-spin" />;
if (isLoading) return <p>Loading...</p>;
<Skeleton className="h-4 w-32" />   // hand-built skeleton in a page
```
